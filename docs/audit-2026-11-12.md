# Static audit, 2026-11-12

**Status (2026-11-12, the same day):** every finding below is fixed (CHANGELOG, "the fixes of the static audit"),
checked by two reviews. The "needs a GPU" items: #1 measured (split-K is not bit-identical to one pass: KL mean
0.00067, max 0.0017 on the 27B, the same greedy tokens; the comment says so now); #4 fixed (the probe throws);
#2 and #3 wait for B60 / B580 and 140T owners.

**Scope:** a read-only audit of the whole repository — the engine and its kernels, the multi-GPU and Xe2 parts, the
server and the tools. **Nothing was run:** no `runz`, no `serverz`, no GPU work, no build. Every finding below was
checked in the source (file and line given); a claim that needed a GPU is listed under "Needs a GPU" instead of
being called a bug.

**What was looked for:** potential bugs and stale state, lockups and waits without a limit, compiler and build
flags, tile / work-group / sub-group sizes, local (SLM) sizes, failsafes (present, missing, or checking the wrong
thing), memory leaks and lifetimes, and sizes or indices taken from a model file, a request or an env var without a
check. The classes of the three audit rounds before this one (2026-11-04, 11-07, 11-10b) were re-checked where the
code has changed since.

## 1. `--ppl-ctx 0` is an integer division by zero

**File:** `zero/runz.cpp:388` (parsing), `:867` (use)

```cpp
else if (a == "--ppl-ctx") ppl_ctx = atoi(next());                 // 388: 0, negative, "abc" -> 0
...
int nchunks = (int)(all.size() / ppl_ctx);                         // 867: ppl_ctx == 0 -> #DE, process dies
```

`--ppl-ctx` is one of the few runz options with no range check (`--slots`, `--gpus`, `--budget` and the ppl score
options are all clamped or guarded). A typo (`--ppl-ctx 0`, or `--ppl-ctx` followed by a flag name, since
`atoi("--ppl")` is 0) ends the process with SIGFPE / 0xC0000094 before anything is measured. A negative value is not
a crash but silently gives 0 chunks (the `int` becomes an enormous `size_t`); `ppl_dump` would then write an empty
file and the run reports a perplexity of 0 chunks.

**Fix:** right after the loop, before `need` is computed:

```cpp
if (ppl_ctx < 2) throw std::runtime_error("--ppl-ctx must be at least 2 (a chunk needs a scored half)");
```

(`runz --help` says 512 default; 2 is the smallest value the scoring loop can use: `from = ppl_ctx / 2` must leave
at least one scored position, and `ppl_ctx - 1 > from`.)

## 2. Three CPU references are built with `/fp:fast`

**File:** `build.ps1:29`

```powershell
$fp = if ($name -match '^(ref_forward|ref_whisper|test_|vision_test)') { '/fp:precise' } else { '/fp:fast' }
```

`tools/ref_qwen3a.cpp` (the Qwen3-ASR encoder reference), `tools/gemma4v_ref.cpp` and `tools/gemma4a_ref.cpp` are
all "f32 CPU reference" programs by their own headers, but none of the three matches that regex, so all three are
compiled with `/fp:fast` — while the two references that do match get `/fp:precise`. `/fp:fast` lets MSVC contract
`a*b+c` into FMA and reorder, so those three references are not the IEEE f32 reference the checks assume. The
encoder checks (`asr_testz --ref`, the vision / audio encoder tolerance checks) compare against them.

**Impact:** small numbers, but in the wrong direction: the *reference* is the less accurate side, and a tolerance
that was measured against it (e.g. "encoder within 1e-3") has an unchecked bias from the build flags. It also means
two references built by the same script behave differently.

**Fix:** match the tool name, not a prefix list:

```powershell
$fp = if ($name -match '^(ref_|test_|vision_test|.*_ref$)') { '/fp:precise' } else { '/fp:fast' }
```

and note in the comment that every `*_ref` / `ref_*` program is a reference. After the change, re-check the
tolerances of the audio / vision encoder checks (they are diagnostic, not part of the KL gate).

## 3. The kernel cache grows without limit and its temporary file is shared

**File:** `zero/clrt.h:1075-1130`

The cache is keyed `fnv1a(src + "\x01" + opts + "\x01" + device_id)` under `<data dir>\kernels` — correct and
versioned by source and driver. Two problems:

1. **No pruning.** Every new option combination (each `-DQTYPE`, `-DGROUPS`, `-DHD`, `-DTM`, `-DSRC`, `-DHPG`, an
   `ARC_*` experiment, a driver update) writes a new binary and nothing is ever removed. On this laptop:
   `~/.inferzero/kernels` = **1.4 GB, 2,786 files**. There is no `--kernels` cleanup, no age limit, no size cap.
   A driver update invalidates every file (the driver version is in `device_id`) and they all stay behind.
2. **Shared `.tmp` name.** `const std::string tmp = path + ".tmp";` — if two processes compile the same kernel at
   the same time (`runz` and `serverz`, two servers, a benchmark script), both truncate and write the same
   `.tmp` and then rename it: the installed file can be a mixture. It self-heals (a damaged module is detected,
   the cache file removed, and the kernel compiled again — `clrt.h:1146`), but the recovery deletes the other
   process's now-good file, and the second process pays the compile again.

**Fix:** (a) `tmp = path + ".tmp." + <pid>` (or a random suffix) and `rename` still replacing atomically; (b) a size
cap and a sweep at start: delete cached files older than the newest N GB or older than ~60 days when their count
exceeds a limit, best done in the server's start (`server_load.h`) and in `runz` before an engine is made, so a
prune cannot race with a load in this process.

## 4. `--arch:AVX2` without a CPU check

**File:** `build.ps1:35`

Every exe is built `/arch:AVX2`. Nothing (no `__cpuid`, no `IsProcessorFeaturePresent`) checks for AVX2 before the
vector code runs, so on a CPU without AVX2 — an Arc A380 or A310 in a pre-Haswell machine is the realistic case, and
those cards are supported — the exe dies at the first `vfmadd`/`vbroadcast` with 0xC000001D (illegal instruction),
before it can print anything. `/fp:fast` + `/arch:AVX2` (+ `/Oi`) on the model path also means the *host* side of
the arithmetic (dequantization of embedding rows, the CPU references, the samplers' reductions) is contracted;
that is covered by the KL checks on this machine but not by anything at start.

**Options, in order of preference for a project that ships to strangers:** (a) keep `/arch:AVX2` and refuse at start
with a clear message (`IsProcessorFeaturePresent(PF_AVX2_INSTRUCTIONS_AVAILABLE)`) instead of an illegal
instruction — a 10-line change in `src/app_dir.h`'s neighbours or each `main`; (b) build two paths; (c) `/arch:SSE2`
for the tools that do not need it. (a) is enough to turn a silent crash into a message.

## 5. `video_budget` can dereference a released adapter

**File:** `zero/clrt.h:481-496`

```cpp
for (UINT i = 0; !ok && f->EnumAdapters1(i, &a1) != DXGI_ERROR_NOT_FOUND; ++i) {
  DXGI_ADAPTER_DESC1 d;
  a1->GetDesc1(&d);                                    // a1 released in the previous iteration
  ...
  a1->Release();
}
```

If `EnumAdapters1` fails with an error other than `DXGI_ERROR_NOT_FOUND` (a driver reset, an out-of-memory, a
display change during the enumeration), the body runs with `a1` pointing at the adapter the previous iteration
already `Release()`d — a use-after-free in the DXGI runtime, not in our code. `GetDesc1`'s HRESULT is ignored too.
This is the path `--prof`/out-of-memory messages use, so it is the path taken exactly when the GPU is already in
trouble.

**Fix:**

```cpp
for (UINT i = 0; !ok; ++i) {
  IDXGIAdapter1* a1 = nullptr;
  if (f->EnumAdapters1(i, &a1) != S_OK || !a1) break;
  DXGI_ADAPTER_DESC1 d{};
  if (SUCCEEDED(a1->GetDesc1(&d)) && d.VendorId == 0x8086) { ... }
  a1->Release();
}
```

## 6. `ds_norm_rope`: a fixed `float v[32]` indexed by `K/16`

**File:** `zero/kernels/ops_ds41.cl:236-246`

```c
const int r = get_group_id(1), l = get_sub_group_local_id(), per = K / 16;
...
float v[32];
for (int i = 0; i < per; ++i) v[i] = s[i];          // per > 32 -> past the array, into another lane's registers
...
for (int i = 0; i < per; i += 2) { ... v[i + 1] ... } // per odd -> one read past the lane's 16 values
```

`K` is the row width: `hp.head_dim` (512, `per` = 32 exactly), or `d.ID` (128, `per` = 8). Both are fine today and
guarded elsewhere (`head_dim != 512` is refused, `d.ID != 128` is refused), so this is latent, not live. It is
worth pinning because the array is sized for the largest caller and the kernel itself does not know it.

**Fix:** a compile-time check in the kernel is not possible (`K` is an argument), so add to `engine_ds41.h`'s
`ds_norm_rope()`:

```cpp
if (K > 512 || K % 32) throw std::logic_error("ds_norm_rope: K must be <= 512 and a multiple of 32");
```

## 7. `win_all[16]` and `& 15`: exactly one work-group size works

**Files:** `zero/kernels/decode.cl:786-787` and `:1435-1436` (`gemv`, `gemv_v`), `zero/kernels/decode_moe.cl:95-96`
and `:269-270` (`moe_gateup_q`, `moe_down_q`)

```c
__local uint win_all[16][WIN_CALLS * 16];
__local uint* win = win_all[get_sub_group_id() & 15];
```

Correct for every launch there is today: `matmul1`/`gemv_gu` pass `l1 = 256` (or `xe2_gemv_wg()`, 64 or 256) and
`moe_gateup_q`/`moe_down_q` are launched with 256 — 16 sub-groups of 16 lanes, and the `& 15` is exact. Above 256
(the driver's default is 1024 per work-group) the 17th sub-group would share the 1st one's window: a silent data
race, not an error, because `& 15` masks instead of failing.

**Fix:** make the assumption explicit, e.g. `#if`-guard the array on `TPW`-style defines, or use
`win_all[get_num_sub_groups() <= 16 ? ... ]`… simplest is a guard at the top of the kernel:

```c
if (get_num_sub_groups() > 16) return;  // (never: the launches use 256 work-items)
```

and one line in `clrt.h`'s `clEnqueueNDRangeKernel` when `ARC_ZE_KPROPS` is on (it already prints per-kernel
private / spill bytes): print a warning when `ls[0]*ls[1]*ls[2] > 256` for a kernel whose name starts with `gemv`
or `moe_gateup`. Cheap insurance against the next experiment.

## 8. Tuning env vars with no validation

Two places accept any integer and then use it in a grid or a define:

- `zero/engine.h:942` `gemv_v_rows`: `ARC_GVROWS` is returned as-is. `0` is treated as unset (fine), a negative or
  a value larger than the row count is not: `sgs = (N + grows - 1) / grows` becomes 0 → `g1` 0 → `clrt.h` skips
  the launch and the output buffer keeps whatever it held (a silent wrong answer, no message).
- `zero/engine_moe.h:87` `ARC_MOE_TM_SMALL`: any positive value becomes `-DTM=n` for the MoE tile kernels, which
  were written and measured for 1, 2, 4, 8, 16.

The rest of the knobs are clamped or compared against a fixed set (`ARC_GEMM_TM`, `ARC_GEMM_CG`, `ARC_ATTN_DEC_SMAX`,
`ARC_DS_ATTN_HPW`, `ARC_H8_HB`, `ARC_FA_*`, `ARC_TP_PIPE_PIECES` …). These two are the exceptions.

**Fix:** `if (force <= 0 || force > w.N) force = 0;` in `gemv_v_rows`, and a clamp to `{1,2,4,8,16}` for
`ARC_MOE_TM_SMALL` (warn once as `ARC_GEMM_TM` does).

## 9. `lws = nullptr` launches: the group size is silently shrunk to divide the grid

**File:** `zero/clrt.h:861-866`

```cpp
for (int d = 0; d < 3; ++d)
  while (ls[d] > 1 && gs[d] % ls[d]) --ls[d];   // the largest divisor not above the driver's suggestion
```

When a caller passes no local size, the driver's suggestion is reduced until it divides the grid — necessary,
because Level Zero runs whole groups only (and a group size that does not divide is a hard error two lines
later). The consequence worth knowing: such a kernel cannot read its own group size for a layout, and the group
size it gets is data-dependent (`hd / 2` rows for `rope_table`, `T` for other launches). Every `run(..., nullptr)`
call site today indexes nothing by `get_local_size()` **except** the loops of the form
`for (i = get_local_id(0); i < n; i += get_local_size(0))`, which are size-agnostic. That holds for the 21 such
launches I checked (`rope_table`, `softcap_rows`, `attn_fa_gc`, the `ds_*` kernels, `ple`, `hc_combine`, `ffn_add`,
`moe_gateup` tile sweep, `dfl`) — so this is a documentation item, not a bug: it should be a rule in `AGENTS.md`
("a kernel launched without a local size must not depend on its work-group size").

## 10. `folder_reachable`: a thread and 2 s per dead folder

**File:** `tools/server_catalog.h:76-101`

Every model list spawns a detached thread per candidate model folder and waits up to 2 s for each; a folder whose
thread is still hanging is remembered in a static map that is never cleaned. With an unplugged network drive in
`model-dirs.txt`, each model list (which the web UI asks for on every open) blocks 2 s per dead folder, and the map
keeps one `shared_ptr` per folder forever. Memory-wise trivial; the latency is user-visible. The threads hold only
a `path` and a `shared_ptr`, so no lifetime bug.

**Fix, if it ever matters:** cache "unreachable until <time>" for, say, 60 s instead of re-waiting per list, and
collapsed the map when it exceeds a few dozen entries.

## 12. Launcher: no check of a repository file's path before it is joined and written

**Files:** `scripts/hf-get.ps1:50-78` (`Get-HfFiles`), reached from `scripts/get-models.ps1:23-33` with paths taken
from a pasted Hugging Face link (`scripts/launcher-downloads.ps1:20-30`).

```powershell
$e = $tree | Where-Object { $_.path -eq $f } | Select-Object -First 1   # only the repository's own listing
if (-not $e) { throw "$Repo has no file $f" }
$dst = Join-Path $snap ($f -replace "/", "\")
New-Item -ItemType Directory -Force (Split-Path $dst) | Out-Null
... Move-Item $part $dst -Force
```

`$f` is a path the user pasted (URL-decoded, leading `/` trimmed) and it is only compared against the repository's
file list. Nothing refuses `..` segments, a leading `\`, a drive letter or a UNC name; `Join-Path` with an absolute
`$f` replaces the base folder, and with `..\..` it walks out of the snapshot. A repository can list such a name
(anyone may create one) and a link the user pastes may carry it, so the file is written wherever the payload names —
a Startup folder, or a network share (an NTLM hash leak) — with the size check and the LFS SHA-256 of the repository's
own file satisfied. The same `Join-Path $snap ($p -replace "/", "\")` copies a `mmproj` in `scripts/get-models.ps1:29`.

**Fix**, in `Get-HfFiles`, before any join (the mirror of `proj::` / `files::safe_name` on the C++ side):

```powershell
if ($f -match '^[\/]' -or $f -match '^[A-Za-z]:' -or $f -match '(^|/)\.\.(/|$)') { throw "$f is not a path inside $Repo" }
$dst = [IO.Path]::GetFullPath((Join-Path $snap ($f -replace "/", "\")))
if (-not $dst.StartsWith([IO.Path]::GetFullPath($snap) + [IO.Path]::DirectorySeparatorChar)) { throw "$f leaves the cache folder" }
```

and the same prefix check for the `mmproj` copy.

## 13. Launcher: arguments that can hold a space are not quoted

**File:** `scripts/zero-server.ps1:1097`

```powershell
$srvArgs = @("-m", "`"$($m.path)`"", "--port", $Port, "--ctx", $ctxArg, "--alias", $m.alias, ...)
```

The model's path is quoted, the alias is not: `Start-Process -ArgumentList` joins the array with spaces and adds no
quotes of its own, so an alias with a space (set by the user, or carried by a package) splits into two arguments and
the server either refuses to start or takes the wrong alias. `--draft $m.draft` has the same shape. The recorder
already quotes its strings (`zero-server.ps1:942`).

**Fix:** one helper, `function Q($x) { '"' + ([string]$x).Replace('"','') + '"' }`, used for `-m`, `--alias` and
`--draft`; or start the server with the command line `$srvCmd` (already built with quotes for `server.json`).

## 14. HTTP: a body has a per-read timeout but no total deadline

**File:** `src/http.h:422-470` (the headers' deadline), `:477-540` (the body)

The headers get a total 60 s deadline (the slowloris fix). The body gets only `SO_RCVTIMEO = 30 s` per `recv`,
re-armed at every read, so a client that sends one byte every 29 s holds its connection — and one of the
`kMaxConns = 64` slots — for `len * 29 s`, up to 256 MiB. With remote access on, a stranger can take all 64 slots and
the server stops answering; locally, a program on the same computer can. The 1 GiB body budget does not push back on
a trickle (almost nothing is ever added to `rq.body`).

**Fix:** a body deadline in the header deadline's style: a floor of, say, 60 s plus 1 s per MiB of `Content-Length`
(or per MiB received, when chunked), checked in both body loops; past it, close with 408.

## 15. `CancelIoEx` on synchronous pipes, then `join()`: a wait that is not guaranteed to end

**Files:** `tools/server_terminal.h:196-202`, `tools/server_mcp.h:383-390`

Both read the child's output on a thread with a *synchronous* `ReadFile` on a `CreatePipe` handle, and both end with:

```cpp
for (int k = 0; k < 20 && !read_done; ++k) Sleep(100);
if (!read_done) CancelIoEx(rd, nullptr);
reader.join();
```

`CancelIoEx` is documented for *asynchronous* I/O; on a synchronous read it is best-effort, and the read returns
only when the pipe's write end closes. Normally it closes (the parent closed its copy, the job object killed the
children), so this ends. It does not end when a process escaped the job and still holds the pipe — the case the
comments name (a program started through COM or WMI) — and then `join()` waits until that process exits: a request
thread (or the server's shutdown) waits with it.

**Fix, in order of effort:** (a) leave the reader thread detached with everything it touches in a `shared_ptr`
(buffer, done flag, handle) so there is no `join()` at all — the thread ends whenever the pipe closes; (b) use pipes
that support overlapped I/O (`CreateNamedPipe` with `FILE_FLAG_OVERLAPPED`, reads with `OVERLAPPED`), where
`CancelIoEx` is reliable; (c) at minimum close the read handle before `join()` — a race with the reader's own
`ReadFile`, so (a) or (b) is better.

## 16. MCP: a reply is kept for any id

**File:** `tools/server_mcp.h:458-461`

```cpp
if (!has_id || !m["id"].is_number()) return;
std::lock_guard<std::mutex> lk(mu_);
replies_[m["id"].as_int()] = std::move(m);
```

Every message from the child with a numeric `id` is stored, whether or not a request waits for it, and the entry of
an answer that arrives after its request timed out is never removed before `cleanup()`. A misbehaving MCP server (a
program the user configured, but one a package's installer can write) grows that map without bound.

**Fix:** keep the ids actually sent and not yet answered; store a reply only for one of them, and erase the id when
the request throws (timeout / cancel). A cap (say 1,024 entries, oldest dropped) is the cheap version.

## 17. Web UI: media from a stored chat is not run past `safeUrl`

**File:** `webui/index.html:1398-1404` (`mediaEl`)

`a.href` is set only when `safeUrl(m.url)` accepts it — the right defence, since a stored or imported chat can name
a `javascript:` URL — but the image and audio branches set `src` directly:

```js
if (m.kind === "audio") { const a = document.createElement("audio"); a.controls = true; a.src = m.url; return a; }
if (m.kind === "image") { const im = document.createElement("img"); im.src = m.url; im.alt = alt; return im; }
```

No browser runs `javascript:` from an `img` / `audio` `src`, so this is not an XSS today; it is the same untrusted
value as the link, checked less. **Fix:** `if (m.url && safeUrl(m.url))`, else render the chip as a download link, as
the document branch does.

## Needs a GPU (not called bugs here)

1. **Split-K and the "bit-identical" claim.** `zero/engine.h:1169-1181`: with `K > 8192` the reduction is cut into
   ~17-superblock pieces, each running the GEMM over its own `[s_begin, s_end)` and later pieces *accumulating* into
   `C`. That changes the order of the float additions per output element compared with one full pass, so
   "bit-identical" in its comment can only mean "unchanged versus the previous default". Worth one
   `--dump-logits` before/after with `ARC_GEMM_SPLIT=0` on a long-K layer (the 27B's FFN) to say which it is. The
   *rows per sub-group* changes (`gemv1_rows`, `grows`) are genuinely order-preserving: a row's 16 lanes reduce in
   the same tree whatever row they hold.
2. **The default XMX attention (`attn_x`) on a card whose DPAS we have never measured.** Its start-time check
   (`attnx_check`, `zero/xe2/engine_xe2.h:195`) is good — one kv head, 40 tokens, 48 slots, three tiles, last one
   partial, compared bit for bit — but it runs one shape. A `f33_sweep` run on a B60/B580 with
   `ARC_ATTN_XMX=1` vs `0` on a long Qwen prompt with an image (`nc_lo/nc_hi` set) would close the last gap.
   For Qwen the engine never passes `nc_*` to `attn_q8` (only Gemma's `attn_fa_*` uses image spans), so this is
   narrower than it sounds.
3. **`gdn_chunk_x8` on an Arc 140T.** Still the open item of QUEUE F33.1: "XMX DIFFERED" there, layout checked on
   paper, precision the likelier cause. Nothing in this audit changes that; `ARC_GDN_XEMU=8/16` on the laptop is
   the only way to see it without the card.
4. **Peak-bandwidth accounting for `--read-gbs`.** `engine.h:140-172` allocates 256 MB and `_Exit(1)`s if the
   allocation fails; that is a diagnostic tool, but on a machine where the GPU share is nearly full it exits the
   process instead of reporting. Low; only mention because it is a "no failsafe" case by choice.

## Checked and clean (with what was verified)

- **Freeing and lifetimes of GPU memory.** Every engine allocation goes through `buf()` / `mems_`, sub-buffers
  before parents in `release_all`, `views_`/`from()` cleaned in `free_buf`, `host_ptrs_` (tight-plan weights),
  `mtp_xbuf_`, the npu block (`npu_teardown`: USM import freed, then `VirtualFree`), `dfl_close`, `kcache_` (kernels
  before modules), `read_gbs`'s kernel (released, the 11-10b L3 fix is in). `clEnqueueMapBuffer`'s host copy is
  unmapped on both paths in `upload_padded`; the thread-local `maps()` list has one user and it unmaps.
- **Memory-generation guard for the argument cache** (`zrt::mem_gen`, checked at each `clSetKernelArg`) is correct
  and is what closes the 2026-11-04 class of crash. `clReleaseKernel` clears `zrt::last_k`.
- **Waits.** Single GPU: `UINT64_MAX` on purpose (TDR is the limit; documented). Split models: `sync_timeout_ns` +
  `abort` + `fault`, 100 ms pieces, re-read each piece, `GpuWaitError` rather than an exit; the pipelined sums
  (`tp_reduce_rs_pipe`) give every put/sum an event, the copy list is waited for before reuse, `put_n`/`res_n`
  counters are `acq_rel`, and the f16 failsafe decides from flags read after a barrier by every GPU alike. The
  server's `gen_cv_` batching cannot deadlock: `GenLeave` notifies on every exit path, the leader clears
  `gen_wait_` before running, and the predicate includes `gen_active_ - gen_wait_.size() <= 0`, so the last
  request always runs alone. `claim_slot`'s `busy` flag is RAII-set (`SlotFree`, destroyed while the lock is held)
  and `use_slot` is called before `busy = true` so a throwing bind cannot strand a slot.
- **Local memory sizes** against the 64 KB limit, worst configuration reachable: `attn_q8` tile 32 KB at HD 512
  (2 buffers); `attn_ps` `sp` ≤ 8 KB + tile; `attn_fa_g` with `FA_ROWS` ≤ 32 and head ≤ 256 ≈ 32.5 KB (and
  `#error` forbids `FA_ROWS>1` with f16 K); `attn_fa_gh` `sk`+`sv` ≈ 49 KB at HD 512 (half V) and R>1 is never
  chosen at HD 512; `decode_w8_sl` capped at 32 KB by construction; `gemv` 8 KB; `h8` ≈ 4.1 KB; `ds_topk` 9 KB;
  `whisper.cl` ≤ 8 KB. `#error` guards exist for the two tile-divisibility assumptions (`attn_ps`, `moe_gemm`).
- **Work-group / sub-group assumptions** that are checked in the hparams: `n_head % n_head_kv`, `attn_nsp()` power of
  two (the 11-10b-class tile-copy bug), NE ∈ {256, 512} (a power of two for `moe_scan`'s scan, and ≤ the max group
  size), `K % 256` everywhere a GEMM is used (`load_w_pad` pads small-block rows and passes `padded_k(K)`), `Mp % 16`,
  `N % 16`, HD ∈ {128, 256, 512}, DeepSeek's `TOPK ≤ 2048 = DS_TK_MAX` and `cand_k ≤ 2048`, `ID == 128`, `nc == 512`
  for `ds_attn`.
- **Bounds checks in the new DeepSeek kernels** (11-11/12): `ds_topk`'s `idx[DS_TK_MAX]` cannot overflow because
  `base < kk ≤ k ≤ 2048`; the radix loop keeps `need ≥ 1`; `ds_block_max` writes only `b < nbmax`; `ds_cand_map`
  indices are `b < ceil(nv/bs) = nbmax`; `ds_norm_rope`'s early return is only taken in mode 2, where no sub-group
  reduction follows (comment says so, and the code agrees).
- **Kernels that return before a barrier**: every hit of a mechanical sweep was checked — the guards are
  work-group- or sub-group-uniform (`get_group_id`, `get_sub_group_id`, a lane-uniform condition), or the barrier is
  a `sub_group_*` with one sub-group per work-group (`lws` 16×1). `moe_rg`'s early return is `get_group_id(1)`-based
  by design ("before the staging").
- **Model-file guards** (`gguf.h`, `engine_load.h`, `engine_setup.h`): tensor dims/lengths, `expect()`, `load_vec`,
  `N > Np`, `nelements()` vs `INT32_MAX`, embedding width vs `n_embd`, hparam ranges, `full_attention_interval`
  before its index use, `expert_used_count ≥ 1`, QSA ratio set. The 11-10b fixes (S1-S7) are in.
- **Server input paths**: `--slots` / `--gpus` / `--asr-slots` / `--session-cache-gb` clamped; `--image-max-tokens`
  and `--image-min-tokens` parse with `atoi` but are only applied when `> 0`; body budgets (1 GiB total, 256 MiB a
  request), header and read deadlines, the connection cap; foreign-origin handling unchanged from the 10-31 fixes.
- **Leaks in hot paths**: no `new` outside `clrt.h`'s ZMem/ZProg/ZKernel/Dev (all owned), no `malloc`, no
  `strcpy`/`sprintf` outside `snprintf`, `fopen` call sites all close (I checked the 21 in `zero/` and `tools/`).

## Checked and clean, second pass

The parts the first report left out (web UI, launchers, parsers, speech state machines, MCP, terminal, remote
access, `web_fetch` / `web_view`) were read in this pass; this is what they were checked for, and what held.

- **`web_fetch` (SSRF).** `webt::public_v4` refuses 0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24,
  192.0.2.0/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/4 and up; IPv6 mapped, compatible, NAT64 and
  6to4 addresses are judged by the IPv4 they carry, while Teredo, ULA, link-local, site-local, multicast and
  documentation ranges are refused. The host name is checked, then WinHTTP's *connected* address is checked again
  (`WINHTTP_OPTION_CONNECTION_INFO`) — that is what closes DNS rebinding. No proxy; redirects by hand (6 hops, host and
  port re-checked at every hop); the body is capped and a cut body is flagged; every wait has a deadline.
- **`web_view`.** Edge's traffic goes through an in-process proxy that serves only processes inside a running
  render's job object (PID from the TCP table, then `IsProcessInJob`, retried ~100 ms), only to public addresses of
  names whose every resolved address is public, only on non-service ports, one request per connection, with byte and
  time caps. A rendered page opens in a `srcdoc` frame sandboxed without `allow-same-origin`, under a CSP that
  allows https only (so not even an `<img>` reaches `http://127.0.0.1`), and the server refuses `Origin: null`.
- **HTTP framing and remote access.** Conflicting `Content-Length`s and `Transfer-Encoding` together are refused; a
  chunk's size line is capped at 4 KiB, trailers at 64 KiB, every chunk's trailing CRLF checked, the body against
  `kMaxBody` (256 MiB) and the 1 GiB budget; the headers at 1 MiB with a 60 s deadline. Password: PBKDF2-HMAC-SHA256,
  200,000 rounds, random salt, constant-time compare, HttpOnly + Secure + SameSite=Strict cookie, sessions in memory
  only; lockouts per visitor (8 / 15 min) and global (40) with in-flight guesses counted and the visitor map bounded
  at 10,000; forwarding headers on a non-tunnel host refused, so a tunnel cannot make a request look local.
- **Document parsers.** `inflate.h` never reads outside its input, refuses over-subscribed Huffman codes, and caps
  its output (no zip bomb); `zip_entry` bounds every offset and length against the archive. The PDF parser has a work
  budget (512 MB + 3x the file, charged per parse and per decoded stream), depth caps (64 object values, 32
  references, 4 form XObjects) and a step cap for content streams; page counts checked, `Indexed` palettes clamped to
  255, images to 16384 a side / 64 MP, decoded streams capped. `docx` / `xlsx` / `pptx` read their parts under 64 MB
  caps, with no recursive XML walk; `doc_template` re-zips through its own directory reader that bounds every field.
- **File names and project paths.** `files::safe_name` takes the base name only, strips leading dots and spaces,
  refuses device names (`CON`, `NUL`, `COM1`...) and keeps 80 bytes without splitting an extension; `files::valid_id`
  is alphanumeric plus `-` / `_`. A project file (`project:<id>/<rel>`) refuses `..` segments, then canonicalizes and
  requires the result under the project's root (links and junctions followed); a project folder may not be the data
  folder, inside it, or a temp folder.
- **Audio / video and images.** The MP4 box walker compares each box with the room left instead of `a + len` (the
  wrap-around hang of 2026-10-28 is fixed) and caps a level at 100,000 boxes and `moov` at 64 MB; a WAV header's sizes
  are clamped to the file. Images are decoded by WIC with the dimensions checked *before* the pixel buffer is
  allocated, and OCR's page images take the same limits.
- **Speech server state.** `EngineTurn` is RAII-balanced per live task (`demand(+n)` on queueing, one `Done` per task,
  declared before `live_mu_` is taken and destroyed after it, so no lock-order inversion and no leak on an exception);
  `live_q_` is never emptied without its `Done`. Live uploads are deduplicated by `offset` / `since`, so a retried
  request whose answer was lost is not written twice; the page caps what it holds at 600 s and saves the unsent rest
  as a WAV; a microphone that disappears is reopened with backoff.
- **Web UI.** Every `JSON.parse` is in a `try` (the 2026-10-31 finding); Markdown is rendered from *escaped* text,
  links limited to `http(s)` / `mailto` with a character class that cannot leave `href`, `<br>` the only HTML kept;
  a stored chat's file link goes through `safeUrl`; \"Open\" uses the sandboxed frame; the event stream skips events
  that are not JSON and stops after 10 minutes without output; code blocks are escaped and the download uses a
  `text/plain` blob.
- **Launchers.** Downloads resume (`curl -C -`), verify the size and, where the API gives it, the LFS SHA-256, use
  `--speed-limit` / `--speed-time` so a stalled connection ends instead of waiting forever, and never execute what they
  download (an update opens the releases page). `Get-AppDir` moves an old data folder once and rewrites the paths in
  the state files with escaped, boundary-checked regexes. Every script is ASCII (PowerShell 5.1 reads a BOM-less
  script as ANSI).
